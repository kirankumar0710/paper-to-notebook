Tests

How the 462 tests are organised and how to run them. Every test has one level, unit, integration or end-to-end (E2E), and tests of a security defence also carry a security marker. Apart from two opt-in E2E conversions, the tests use scripted models, so they make no API calls and need no keys.

1. Test levels and the security marker

Tests are grouped with pytest markers rather than separate folders: most files test one feature at several levels (test_verify.py has unit tests, real subprocess runs, HTTP tests and security tests), and a security test is also a unit or integration test. The markers are registered in pyproject.toml with --strict-markers, so a misspelt marker is an error.

Default · no decorator

unit

One function or class, with fakes for everything around it. No server, subprocess or network. Tests without a level marker are marked unit in tests/conftest.py.

@pytest.mark.integration

integration

Several parts together: requests through the FastAPI app (TestClient, with all middleware), the run check's real sandbox subprocess, or a real local HTTP server.

@pytest.mark.e2e

e2e

The real dashboard in headless Chrome (Playwright) against a live server, the way a user uses it. In tests/e2e/. Never run by default, by ./check.sh or in CI; run with ./e2e.sh.

@pytest.mark.security · added on top

security

Tests a defence described in Security hardening. It combines with a level marker, so -m "unit and security" works.

4. Security tests

Each defence on the security page has tests that would fail if it were removed. uv run pytest -m security runs them all.

DefenceTested by
Cross-site guard, no CORS (§3)Cross-site, same-site and null origins get 403 on both convert endpoints before any work; same-origin and scripts are allowed; no Access-Control-Allow-* headers (test_security.py)
DNS rebinding, host allow-list (§3)Loopback hosts are served; rebound hosts get 400 on reads and on POST /convert; configured hosts; the run check needs a localhost Host (test_security.py, test_verify.py)
Security headers (§4)CSP and other headers on the dashboard and API; HSTS only over HTTPS; the browser test checks the dashboard has no CSP violations (test_security.py, e2e/)
Run check (§5)Localhost only by default; no API keys in the sandbox environment; package allow-list (test_verify.py)

API keys (§7)Masked in logs and repr; never returned by /api/config; none in config.toml (test_log.py, test_providers.py, test_progress.py)
Input, files and paths (§8)Upload size and reading limit; arXiv redirects away from arxiv.org refused; page includes stay in api/static/; safe filenames; saves never overwrite (test_arxiv.py, test_notebook.py, test_util.py, test_security.py)

5. The E2E browser tests

tests/e2e/test_dashboard.py runs the real app (all middleware, the real page) on a free 127.0.0.1 port in a background thread, and Playwright opens it at 1440×900. pyproject.toml leaves these tests out of every default run, so ./check.sh and CI never run them; run them by hand:

./e2e.sh             # provider, key and model: from the env, else asks
./e2e.sh -k arxiv    # extra arguments go to pytest
TestModelChecks
test_dashboard_loads_under_the_cspScriptedThe page loads on the Upload tab with no CSP violations or JavaScript errors, and fits one screen
test_tabs_switch_panelsScriptedConfiguration, Download and Metrics tabs switch panels; still no page scroll
test_scripted_conversion_passes_the_guards (also security)ScriptedUpload the example PDF and convert: the same-origin guard and the CSP let the dashboard through
test_upload_example_pdf_with_real_modelRealUpload example/non-linear activation functions.pdf (1 page), convert, download the .ipynb and check it has markdown and code cells
test_arxiv_link_with_faked_mcpRealPaste an arXiv link and convert. The MCP server and the download are faked and return the same example PDF, so arXiv is never contacted, but the real lookup code runs and the MCP log tab fills in
  • Provider and key: ./e2e.sh checks the environment first: PROVIDER, then that provider's key (e.g. ANTHROPIC_API_KEY), then PROVIDER_MODEL. It reports each one it finds (the key only as "found", never shown) and asks for each one missing; a typed key is hidden, passed only to that test run, and never written to a file or logged in full.
  • No provider or no key given: it exits without running anything. To run only the three free dashboard tests without a key, use uv run pytest -m e2e; the two real conversions then skip.
  • Summary: after the run, ./e2e.sh prints a summary (green passed, red failed, yellow skipped): each test with its result, scripted or real model, and time; for each real conversion a line like provider : anthropic model: claude-sonnet-5-5: 8,028 tokens, cost $0.04, 13 cells; then the test counts and the total tokens and cost. The tests write their results to a temporary JSON file (TEST_REPORT_JSON, via the run_note fixture) that the summary reads.
  • Cost: taken from the Metrics tab; information only, it never fails a test. To keep it low, the script suggests a cheaper model (e.g. claude-sonnet-5-5), uses standard speed for Claude, and the example paper is one page.
  • Browser: the installed Google Chrome, else Playwright's Chromium (uv run playwright install chromium); without either the tests are skipped.
  • CSP probe: a script added before the page loads records every securitypolicyviolation; the tests require none.
  • Waits use locators (expect(...).to_be_visible()), not wait_for_function: the dashboard's CSP forbids eval, which that call needs.

6. Fakes, isolation and the only real API calls

  • Models: fake providers (FakeProvider, RepairProvider, ScriptedModel) or fake vendor clients return fixed replies, so no test in ./check.sh or CI calls Anthropic, Gemini or OpenAI, and none needs a key.
  • The only real API calls: the two E2E conversions, run by hand with ./e2e.sh. Their fixture (real_server) skips the test when no provider or key is set, so they can never run, or fail, by accident.
  • arXiv: the MCP server and arxiv.org are always replaced with fakes (FakeSession, httpx.MockTransport), even in the E2E arXiv test, whose fake (fake_arxiv) returns the example PDF while the real lookup code runs.
  • Output folder: an autouse fixture saves notebooks to a temporary folder, never the real output/.
  • Host check: TestClient sends Host: testserver, which is allowed in tests only; the real allow-list is tested in test_security.py.
  • Real processes where it matters: the run check's sandbox, retries against a local HTTP server, and the browser run for real, because faking them would hide the bugs those tests are for.

7. Adding a test

  1. Put it in the file for the feature (or tests/e2e/ for the browser).
  2. Pick the level: nothing for a unit test; @pytest.mark.integration if it uses TestClient, a subprocess or a local server; @pytest.mark.e2e for a browser. Mark a whole class or module (pytestmark = pytest.mark.e2e) when all its tests share a level.
  3. Add @pytest.mark.security if it tests a defence. For a new endpoint that changes state or costs money, add a test that a cross-site request gets 403 before any work (see the security-hardening skill).
  4. Use a fake model. A browser test that needs a real model takes the real_server fixture (it skips without a provider), uses the example PDF, and prints its cost rather than asserting it. Never put a key in a test.
  5. Run ./check.sh.
import pytest

@pytest.mark.integration
@pytest.mark.security
def test_new_endpoint_refuses_cross_site(client):
    response = client.post("/new", headers={"Sec-Fetch-Site": "cross-site"})
    assert response.status_code == 403

8. Coverage and CI

  • ./check.sh runs every test with coverage and fails below 95% (currently 97.8%).
  • CI (.github/workflows/ci.yml) runs ./check.sh on every push and pull request to dev-ver-5.0: unit, integration and security tests. E2E tests never run in CI; they need a browser and, for two of them, your API key.
  • Before committing, run ./check.sh; while working, a quick uv run pytest -m unit is enough. Run ./e2e.sh after dashboard changes.
